## Overview

Moshi-Finetune is a repository for fine-tuning Moshi models (audio dialogue models) using LoRA (Low-Rank Adaptation). The system processes stereo audio files where the left channel represents Moshi's audio output and the right channel represents user input.

## Architecture

### Training Pipeline (`train.py`)
The main training script orchestrates:
1. **Distributed setup**: Initializes NCCL backend for multi-GPU training
2. **Model loading**: Loads Moshi LM and Mimi audio encoder from HuggingFace or local paths
3. **FSDP wrapping**: Wraps model with FullyShardedDataParallel for memory-efficient distributed training
4. **Data pipeline**: Loads stereo audio, encodes with Mimi, interleaves audio/text tokens
5. **Training loop**: Forward pass, loss computation (separate text/audio losses), gradient accumulation, mixed precision updates
6. **Checkpointing**: Saves either LoRA adapters only (for use with moshi.server) or merged full model

### Model Wrapping (`finetune/wrapped_model.py`)
- **FSDP policy**: Each transformer layer becomes its own FSDP shard
- **LoRA handling**: Creates separate FSDP groups for trainable (LoRA) and frozen parameters
- **Initialization**: Rank 0 loads base weights, then broadcasts; LoRA layers initialized with Kaiming uniform (A) and zeros (B)
- **Parameter freezing**: Only LoRA parameters (and optionally embeddings) are set to `requires_grad=True`

### Data Processing (`finetune/data/`)
- **Dataset format**: Stereo WAV files where left=moshi, right=user
- **JSONL manifest**: Lists audio paths and durations
- **JSON transcripts**: Per-file transcripts with timestamps (generated by `annotate.py` using Whisper)
- **Interleaver**: Combines audio tokens (from Mimi at 12.5Hz, 9 codebooks) with text tokens (from SentencePiece)
- **Batching**: Handles padding, masking, and proper token alignment for audio/text streams

### Loss Computation (`finetune/loss.py`)
- **Text loss**: Cross-entropy on text tokens with reduced weight on padding tokens (`text_padding_weight`)
- **Audio loss**: Cross-entropy on audio codebooks with higher weight on first (semantic) codebook (`first_codebook_weight_multiplier`)
- **Total loss**: Sum of text and audio losses

### Configuration (`finetune/args.py`)
All training parameters are specified in YAML files:
- **Model paths**: HuggingFace repo ID or local checkpoint paths
- **LoRA settings**: rank, scaling, whether to fine-tune embeddings
- **Training hyperparameters**: learning rate, batch size, duration, max steps
- **Optimization**: AdamW with OneCycleLR scheduler
- **Mixed precision**: Default bfloat16 for parameters, float32 for optimizer states
- **Checkpointing**: frequency, number to keep, save adapters vs. merged model
- **WandB logging**: Optional integration for metrics tracking

### Checkpointing (`finetune/checkpointing.py`)
- **LoRA-only mode** (`save_adapters=True`): Saves only LoRA weights as `lora.safetensors`, usable directly with `python -m moshi.server --lora-weight=...`
- **Merged mode** (`save_adapters=False`): Merges LoRA into base model, saves as `consolidated.safetensors` (requires more memory)
- **Checkpoint management**: Keeps only `num_ckpt_keep` most recent checkpoints

## Key Implementation Details

### Distributed Training
- Uses PyTorch FSDP with `FULL_SHARD` strategy
- Each transformer layer is a separate FSDP unit
- Backward prefetching (`BACKWARD_PRE`) for overlap
- Supports gradient checkpointing to reduce memory usage

### LoRA Fine-tuning
- Only LoRA parameters are trainable by default (typically <1% of total parameters)
- Optional: Also fine-tune embedding layers with `lora.ft_embed=true`
- LoRA layers inserted into all linear layers in transformer blocks
- Rank typically ≤128 for efficiency

### Audio Processing
- Mimi encoder: Stereo audio → 9 codebooks at 12.5Hz
- Left channel: Moshi's generated audio
- Right channel: User's input audio
- Tokens interleaved with text tokens from SentencePiece tokenizer

### Mixed Precision
- Parameters stored in bfloat16 during forward/backward
- Upcast to float32 for optimizer step
- Downcast back to bfloat16 after optimizer step
- Gradient clipping applied in float32

## Dataset Format

The training pipeline expects:
1. **Stereo WAV files**: Left channel for Moshi, right channel for user
2. **JSONL manifest**: One line per file with `{"path": "...", "duration": ...}`
3. **JSON transcripts**: Per-file annotations with timestamped text (one for each WAV file)

Example directory structure:
```
data/
├── dataset.jsonl
└── audio/
    ├── file1.wav
    ├── file1.json
    ├── file2.wav
    └── file2.json
```

The `annotate.py` script generates JSON transcripts using Whisper with VAD (Voice Activity Detection).

## Common Configuration Adjustments

### For OOM errors:
- Reduce `batch_size`
- Reduce `duration_sec` (but may hurt inference quality)
- Enable `gradient_checkpointing: true`
- Reduce `lora.rank`

### For faster training:
- Increase `batch_size` (if memory allows)
- Use `num_microbatches` > 1 for gradient accumulation
- Adjust `max_steps` based on dataset size

### For better quality:
- Increase `duration_sec` (allows longer context)
- Increase `lora.rank` (more expressive adapters)
- Tune `first_codebook_weight_multiplier` (semantic tokens)
- Adjust `text_padding_weight` (balance text vs. padding loss)
